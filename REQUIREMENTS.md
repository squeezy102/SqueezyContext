## Notes on Writing Good Requirements

- Write what the user experiences, not what the code does
- Include edge cases and exception behaviors explicitly
- Note things that are intentionally NOT included ("This screen does not X")
- If a requirement depends on another, call it out explicitly
- Avoid implementation language — save that for DECISIONS.md
